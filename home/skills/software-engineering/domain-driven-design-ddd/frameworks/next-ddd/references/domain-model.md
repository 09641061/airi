# Optional Rich Client Domain

[Skill overview and workflow](../SKILL.md). Examples target Next.js 16 and React 19.3; verify project versions.

## Optional Rich Client Domain (Separate Example)

This section is **not part of the remote create flow**. Use it only if the frontend actually manipulates a local aggregate with business behavior, such as a product draft that can be renamed independently of the form. Otherwise omit these files entirely. The optional additions are:

```txt
domain/
  errors/business-error.ts
  model/product.ts
  repositories/product.repository.ts
interfaces/schemas/local-product.schema.ts
```

### Entities and Invariants

```ts
// domain/errors/business-error.ts
export class BusinessError extends Error {
  constructor(public readonly code: 'INVALID_NAME') {
    super(code)
    this.name = 'BusinessError'
  }
}

// domain/model/product.ts
import { BusinessError } from '../errors/business-error'

export const PRODUCT_NAME_MAX_LENGTH = 120

export class Product {
  private constructor(
    public readonly id: string,
    private name: string
  ) {}

  static create(id: string, name: string): Product {
    return new Product(id, Product.validateName(name))
  }

  private static validateName(name: string): string {
    const normalized = name.trim()
    if (!normalized || normalized.length > PRODUCT_NAME_MAX_LENGTH) {
      throw new BusinessError('INVALID_NAME')
    }
    return normalized
  }

  rename(newName: string): void {
    this.name = Product.validateName(newName)
  }

  get displayName(): string {
    return this.name
  }
}

// interfaces/schemas/local-product.schema.ts (optional rich-domain boundary)
import { z } from 'zod'
import { PRODUCT_NAME_MAX_LENGTH } from '../../domain/model/product'

export const localProductSchema = z.object({
  name: z.string().trim().min(1).max(PRODUCT_NAME_MAX_LENGTH),
})
```

The ID above is supplied by the owning system, not generated by a mandatory repository method. A ProductName value object is an alternative only if name semantics warrant a reusable immutable concept; a standalone naming service is unnecessary for this private invariant. Domain contains no Zod, React, Next.js, transport, or IO dependencies.

### Aggregates, Repositories, and Services

Aggregates protect local consistency boundaries, not entire screens. Introduce a repository only if it really represents a collection of aggregates manipulated locally:

```ts
// domain/repositories/product.repository.ts (optional rich-domain example only)
import type { Product } from '../model/product'

export interface ProductRepository {
  save(product: Product): Promise<void>
  findById(id: string): Promise<Product | null>
}
```

This is not the remote creation port. Do not add ID allocation to every repository. Domain services express policies spanning concepts that do not naturally belong to an entity or value object (for example, multi-concept pricing), not wrappers around entity methods or command handlers. Add events only for facts with actual consumers and defined publication/delivery requirements; a type alone does not publish anything.
